The project-access question is resolved: an active user linked through user_role_mapping/project_mapping to an active project_master record has project membership. project_master.is_active determines project activity. We will ignore enable_quality for QMS360 access.

Existing per-user QMS360 application access, approvals and role permissions will remain separate. A project mapping will not automatically grant application approval or administrator permissions.

For the approved exception in the shared PRD/UAT environment, QMS360 will match
profile.email to user_master.user_email. Profile UID is not assumed to be the
source user ID. QMS360 will retain reviewed internal UUID links.

setting. This is not verified SSO. Network access must be restricted and the
existing QMS account/application/role approvals remain enforced. No QMS
administrator permission is inferred from Drona roles.

docs/drona/email-exception-handoff.md. The team must review the schema/migration
